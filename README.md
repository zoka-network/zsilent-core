# ZSilent Core

ZSilent Core is a native desktop control center for the Zoka network. It is designed as a privacy-first application that combines wallet, full node, mining, logs, local settings, and network operations in one Material 3 interface.

## Stack

- Kotlin/JVM 17+
- Compose Desktop
- Material 3
- Gradle Kotlin DSL
- Kotlinx Serialization
- Coroutines and Flows
- Ktor HTTP/WebSocket client
- Windows MSI packaging

## Local Development

Common commands:

```powershell
.\gradlew.bat run
.\gradlew.bat build
.\gradlew.bat packageMsi
```

The app looks for Zoka binaries in:

- `../target/release/zoka.exe`
- `../target/release/zokahd.exe`
- `../target/debug/zoka.exe`
- `../target/debug/zokahd.exe`

The first implementation controls the existing Rust binaries through a local process bridge and reads node state through the local RPC API.

## Privacy Defaults

- No telemetry.
- No private keys in logs.
- JSON exports must be encrypted before being enabled.
- Wallet history is local-first.
- Remote node support is planned but disabled by default.

## First Run Flow

ZSilent Core starts in onboarding mode:

1. Choose create wallet or restore seed.
2. Select 12 or 24 recovery words.
3. Set the master password and auto-lock policy.
4. Configure local node and optional mining.
5. Create or restore the real Zoka wallet through the local CLI bridge.
6. Save the generated recovery phrase when creating a new wallet.
7. Enter the dashboard only after setup is complete.

The wallet bridge uses protected process channels instead of command-line secrets:

- `--password-env ZSILENT_WALLET_PASSWORD`
- `--seed-env ZSILENT_RECOVERY_PHRASE`
- `--password-env ZSILENT_NODE_PASSWORD`

The Zoka CLI also supports `--password-stdin` for terminal/automation flows.

New wallet creation passes `--seed-words 12` or `--seed-words 24` to Zoka Core, so the phrase length selected in onboarding is the phrase length generated by the wallet backend.
